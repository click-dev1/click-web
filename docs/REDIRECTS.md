# Legacy redirects

The SOW's 1:1 redirect map (§5): every URL of the earlier sites lands on
the closest page of this one instead of a 404.

`docs/REDIRECTS.csv` is the map itself — one row per old URL with its
destination and the rule that sent it there. That file is the acceptance
evidence; hand it over as it is.

## Where the URLs come from

The Internet Archive's record of `clickmedia.group`, which covers both
earlier sites:

- **WordPress, to mid-2025** — `/creator/*`, `/our-creators/*`,
  `/case-studies/`, one page per campaign, creator filter archives
  (`/genre/*`, `/primary-platform/*`…).
- **Wix, Aug 2025 – 2026** — `/about-1`, `/our-work`,
  `/talentprofiles/*`, `/terms-conditions`.

The archive only knows what it crawled. When CLICK's Search Console
export or Wix page list arrives, add any path it has that the CSV does not
to `EXTRA_PATHS` in `scripts/build-redirects.ts` and regenerate.

## How it resolves

- An old profile of a creator **on the current roster** goes to their
  profile (`/our-creators/bundun-new-format` → `/talent/bundun`). A
  creator's second channel goes to the creator (`more-muselk` →
  `/talent/muselk`).
- Any other old creator or filter URL goes to `/talent`, through one
  catch-all rule per old prefix.
- Old campaign pages that are not on the new site go to `/work`; the new
  site does not claim they are the same campaign.
- WordPress defaults, author archives and Wix pop-ups are **left to 404**
  on purpose — a redirect would pretend they were content.
- Three calls are marked `review` in the CSV for CLICK to confirm:
  `/services` and `/our-maps` → home, `/click-live-program` →
  `/talent-management`.

## Commands

```
pnpm redirects:build            # dry run: counts and review items
pnpm redirects:build --apply    # writes lib/legacy-redirects.ts + docs/REDIRECTS.csv
pnpm build && pnpm start
pnpm redirects:verify           # every old URL, as archived and without its slash
pnpm redirects:verify https://click-web-git-dev-click17.vercel.app
```

`lib/legacy-redirects.ts` is generated — never edit it by hand. Review
its diff before committing. Re-run the build when the roster changes: a
new creator's old URL keeps going to `/talent` until then.

## Safety

- The build never contacts the archive. The map is generated by hand,
  reviewed in git, and shipped as data.
- Archive paths are untrusted. Only plain lowercase slug paths are
  accepted — no dots, no encoding, none of path-to-regexp's syntax
  characters — so nothing from the archive can become a pattern.
- Every destination is an internal path chosen by the script, and nothing
  from the request is carried into one, so no redirect can send a visitor
  off-site. The verifier fails on any off-site hop.
- The generator refuses to write a redirect whose source is a live page.
- The Studio refuses a page slug whose first segment is an old address
  (`reservedSlugs`), because a redirect is checked before any page and
  would make it unreachable.
- Vercel allows 1,024 redirects; the map uses under 60.

## Verified

26 September 2026, local production build: **504 old URLs, 1,007
requests (with and without trailing slash), all end on their expected
page with a 200 in at most two hops.** The two hops are Next's own
trailing-slash 308 followed by the redirect.
